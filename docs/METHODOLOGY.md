# Methodology - How we got there and tools used

## Question asked
"How are our Play Store ratings and what should we fix first?" - as a repeatable check, not a one-off.

## Pipeline
1. **Collect** - CSV with `rating, date, text` + `review_id, app_version, source, source_url`.
   See `docs/DATA_COLLECTION.md` and `scripts/collect_play_reviews.py`.
2. **Clean** - `src/clean_reviews.py`: numeric 1-5 filter, whitespace normalisation, exact-duplicate removal, date parsing, audit log (input/output rows, invalid ratings, empty text, duplicates, unparseable dates, missing URLs).
3. **Classify** - `src/classify_reviews.py`: transparent keyword rules in fixed order (Booking > GPS > Notifications > Login/crash > Check-in > Driver/ops > Support > Other). Keeps primary category plus `all_matched_categories` and heuristic confidence (0.60 base, +0.10 per extra category, +0.05 if multiple keywords hit, capped 0.95). Confidence is NOT a calibrated probability.
4. **Analyse** - `src/analytics.py`: rating distribution, 1-2 star share, monthly trend, category breakdown, version breakdown, version x category matrix.
5. **Prioritise** - `src/prioritization.py`: `priority = 0.40*frequency + 0.35*severity + 0.25*confidence`, each 0-100, weights normalised from sidebar. Severity rubric: Booking 5, Login/crash 5, GPS 4, Check-in 4, Driver/ops 4, Notifications 3, Support 2, Other 1.
6. **Validate** - `src/validation.py`: manually label ~30 per top category into `manual_category`, compute per-category precision/recall and accuracy. Fix rules, keep sample as regression set.
7. **Export** - `src/report_export.py` + dashboard Export tab: classified CSV + Markdown summary.

## Tools
- Python 3.10+, pandas, Streamlit, Plotly, pytest.
- AI coding assistance for scaffolding; all rules and rubric are checked in and editable.
- No auto-scraping in the app; collection is explicit and traceable.

## Demo dataset
`data/sample_reviews.csv` (280 rows, generated by `scripts/generate_demo_data.py`, seed 42) is synthetic and only proves the pipeline runs. Real submission must replace it.

## Assumptions stated
- Public reviews are self-selected and do not represent all users.
- Keyword labels are triage signals; root cause needs telemetry (crash, API, notification delivery, booking, trip events) + support tickets.
- Severity is a proposed rubric, not company priority. Safety escalates separately.
- Do not invent source URLs.

## Repeat cadence
After each release: re-import, compare version cohorts, track rating + reliability metrics, keep before/after notes per ticket.
